P2P · no leader · git-backed

Configuration files that keep themselves in sync.

uRep is a tiny, decentralized replication agent for configuration files. Every node is equal. Every change is a git commit. Every message is encrypted with your cluster token.

Get started Read the spec
docker run 
docker run -d --name urep-app \
  -e UREP_TOKEN='cluster-secret' \
  -e UREP_TAG=nginx \
  -e UREP_PATH=/urep/app.yaml \
  -e UREP_POST_HOOK='nginx -s reload' \
  -v /home/app/app.yaml:/urep/app.yaml \
  -v urep-state:/var/lib/urep \
  urep:latest

Why uRep

Small surface, serious guarantees.

No database to operate, no coordinator to elect. Just files, git, and an encrypted mesh that converges.

01

No leader

Every node is equal. No coordinator, no quorum, no failover dance.

02

Git is the state

Each node mirrors files into a SHA-256 git repo. History is the source of truth.

03

Tag subscriptions

A node listens only to messages tagged for it. A waf node never sees nginx configs.

04

Hooks that travel

Pre/post commands ride with the file and run on the receiver, not the sender.

05

Encrypted by default

One cluster token derives HKDF keys. ChaCha20-Poly1305 protects every frame.

06

Container-first

One image, a couple of ENV vars, and a state volume. urep is the entrypoint.

How it works

Watch. Commit. Replicate. Apply.

The loop is deliberately boring: detect a change, record it in git, send it to matching peers, and let last-write-wins resolve the rest.

1

Watch

inotify on the parent directory. Debounce, re-hash the whole file, detect atomic saves.

2

Commit

Write the mirror, commit with an HLC version, mode, tags, and hook metadata.

3

Replicate

Encrypted FILE_PUT to peers whose tags match. LWW on apply, hooks on the receiver.

watcher ──► commit ──► replicator ──► transport (TCP + AEAD)
   │              │              │
   │              ▼              ▼
   │         repo/ (git)     discovery (UDP multicast + gossip)
   │                             │
   └──────────── ◄── apply ◄── write ◄── hooks
                        │
                        ▼
                   state.json · events.jsonl · peers.json

Quick start

Two containers, one file.

Build the image, then run the bundled two-node smoke test. It starts two peers on the host network, changes a file on one, and verifies that the other converges.

  • Runs entirely in Docker
  • Uses seeds instead of multicast on a bridge/host network
  • Leaves containers running for inspection
  • Cleanup with ./test.sh --cleanup
terminal 
cd urep
make build
./test.sh

# inspect the receiving node
docker exec urep-b urep status
docker exec urep-b urep peers
docker exec urep-b urep log
